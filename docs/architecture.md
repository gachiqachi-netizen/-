# 串个珠系统架构与开发状态

本文以当前仓库为准，区分已经写出的开发基础与仍待接入、验收的能力。产品范围以 `prototype.html` 为参考；本阶段后台重点是珠子上架和订单管理，不实现后台发货功能。

## 当前系统与数据流

```text
微信小程序（miniprogram/）
  ├─ 首页 / 编辑器 / 作品 / 订单 ── HTTPS API ── 应用服务（server/app.py）
  ├─ AI 配、拍照做同款 ────────────┤                ├─ 登录与业务（user_api.py）
  ├─ 3D 示意 / 照片手动试戴       │                ├─ 珠子、模板、订单、用户、分享
  └─ 微信分享入口 ─────────────────┘                ├─ AI 适配（server/ai/）
                                                    └─ 搭配匹配（plans.py、kb/）
运营网页后台（server/static/admin.html） ── 管理 API ──┘
                                       数据：本地 SQLite / 本地上传文件
                                       外部：微信登录、可配置 AI 服务
```

- 小程序通过 `utils/api.js` 和 `utils/auth.js` 访问本地服务，默认地址为 `127.0.0.1:8801`，仅供同机开发。微信登录凭证经服务端换取用户会话；设计及订单接口需登录并限定当前用户。离线草稿保存在设备，已登录时尝试同步，云端设计更新具备版本冲突保护。
- 商品和模板读取 `/api/catalog`；拍照发送图片至 `/api/ai/photo`，从商品目录匹配主珠和配珠；AI 配优先调用 `/api/plans/match` 的方案匹配；完成后的评价使用 `/api/ai/review`。目前客户端语音入口提示使用输入法语音，未接入独立语音识别服务。
- 编辑器内置 WebGL 颜色示意和不可用时的平面回退；照片试戴是设备内手动叠加示意，不是实时手腕追踪，也不是实物贴图的真实渲染。分享由用户主动创建随机快照，公开读取仅包含设计数据。
- 小程序以 `/api/my/orders` 创建待支付订单；服务端检查上架状态、计算金额并保存珠子快照，使用请求编号实现幂等。**尚无真实微信支付、支付回调、退款或供应商履约连接。**旧 H5 存在独立演示下单接口，正式部署必须禁用。
- 运营后台可管理珠子、模板和宣传位，并查看、搜索订单。珠子图片上传目前写本机文件；订单不提供后台发货操作。`ADMIN_TOKEN` 为空时管理 API 拒绝请求，单口令仍仅供开发。

## 按层拆解

| 层 | 当前实现 | 下一步 |
|---|---|---|
| 微信小程序前端 | 已有主要页面、素材编辑、保存与订单入口；JS/JSON 可静态检查 | 在微信开发者工具编译与 iOS/Android 真机完整验收；按 H5 核对功能和交互，处理异常/弱网；3D 真实性单独评估 |
| 客户端接入层 | `utils/api.js`、`auth.js` 封装请求与会话 | 统一超时、重试、失效会话和错误结构；订单确认前刷新商品目录及最终金额；不在客户端保存密钥 |
| 业务后端 | Python 标准库 HTTP 服务，包含目录、用户、设计、分享和订单接口 | 保持清晰边界；支付及回调、鉴权、输入校验和业务审计需按生产要求完成；统一配置和部署 |
| AI 接入层 | 方案库匹配；可配置兼容 OpenAI 的服务或 Claude；结构化结果经过部分校验 | 选定实际模型或 ZerOne Agent 后再配置，补齐超时、失败提示、输入输出校验、监控及内容安全；识别效果需样本评测 |
| 数据与素材 | SQLite JSON 文档表：商品、模板、用户、会话、设计、订单、幂等请求、分享；本地图片 | 根据部署方案选择持久化数据库和对象存储；补迁移、备份恢复、索引和数据生命周期；保留订单成交快照 |
| 运营后台 | 网页，珠子上架与订单查看/查询已具雏形 | 建立正式登录、权限与操作审计；满足最小珠子管理和订单处理需求，暂不开发发货界面 |

## 关键状态与风险

1. 小程序账号及微信支付尚未接入；没有正式 AppID、服务端凭证和商户配置时不能验证登录、分享卡片、支付或真机交易。账号审核期间可继续本地开发，不应以游客占位 AppID 的静态检查代替编译验收。
2. 当前目录客户端在进程中缓存；后台改价或下架后，预览可能仍展示旧信息。服务端下单重新校验、重新计价，但在下单前应主动刷新目录，让用户确认最新金额。
3. `server/README.md` 中部分 H5 说明（本地识图回退、订单状态操作）不等同于当前小程序或后台的行为；以代码及逐端验收为准。
4. 本机 SQLite 与 HTTP 服务没有生产备份、容量、部署及网络边界保障；静态口令、示例价格与推广规则也不能原样用于生产。
5. 用户上传手串照片时会发送到识别服务；手腕照片当前在设备内处理。上线前须按真实数据流提供隐私说明、取得必要授权并核查内容安全及服务提供方的数据处理。
6. 用户当前要求暂不实现发货。微信交易类小程序的正式支付与发货管理要求需在上线前按微信平台实际规则确认，不能因为后台暂无发货界面就认为已满足。

## 优先顺序

1. **本地闭环**：目录刷新与价格一致性、编辑器/订单/AI 接口契约、后台珠子和订单的联调；对登录缺失、材料下架、重复请求、冲突和失败提示做验证。
2. **微信环境验收**：账号审核通过后配置 AppID 与安全服务端凭证，编译、体验版、iOS/Android 逐条验证 3D、照片、分享、设计同步及订单。
3. **生产能力**：确认云环境、数据与存储方案，接入微信支付/回调与退款，后台安全、备份和内容安全；选择 AI/语音方案并实测质量、成本。
4. **发布准备**：校验商家主体、类目、备案、隐私指引及交易规范；真实订单测试和审核通过后再发布。
