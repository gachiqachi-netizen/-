# 06 订单、物流、售后和登录的交互补全

> 基于 `codex/admin-commerce-hardening-v2` 的 `edd9fdf`。后端已经有五组状态（订单、支付、制作履约、物流、售后）和 `allowedActions`，问题出在“给用户看什么、用户能做什么”。
> 本文替代 02 第 7 节（订单与售后）和 02 里关于登录时机的部分。标“需后端”的改动要先做后端。

## 2. 登录：改成“无感登录”，删掉登录页

**原则：用户不需要知道“登录”这件事。** 微信小程序拿 openid 不需要用户授权，`wx.login` 换会话是静默的。

1. **启动时静默登录**：`app.js` 的 `onLaunch` 里调用 `auth.login()`，失败不提示、不拦截；之后任何需要会话的请求，`auth.authorized()` 仍会自动重试登录（已有逻辑）。
2. **删除 `pages/login/login`**，从 `app.json` 移除；所有 `goLogin` 改成直接调用 `auth.login()`。
3. **下单**：点提交时如果没有会话，先静默登录，成功后**直接继续提交**，不跳页、不让用户再点一次。只有静默登录失败时，才在按钮下方显示一行“网络不太好，没能连上服务，点提交再试一次”。
4. **“我的”页**：不再出现“登录”字样。顶部只显示头像和昵称；没有设置过就显示默认头像和“给自己起个名字”，点进去用微信的头像昵称填写能力（`button open-type="chooseAvatar"` 和 `input type="nickname"`）。头像和昵称都是可选的，不设置也能用全部功能。
5. **本机作品合并**：第一次拿到会话时，把本机保存但没同步的作品上传到账号，完成后给一次轻提示“作品已同步”。失败的留在本机，下次再试，不打扰用户。
6. **手机号**：不单独要手机号。收货手机号来自地址（手填或 `wx.chooseAddress`），不做“手机号一键登录”。
7. **开发环境**：开发测试登录（`/api/auth/dev`）改成在 `auth.login()` 内部自动降级，界面上只在开发版的“我的”页底部显示一行小字“开发测试账号”，不再有独立页面。

验收：清空缓存后从首页一路设计到提交订单，全程不出现“登录”二字，订单创建成功；“我的”页能看到这笔订单。

## 3. 订单：一个状态、一条进度、一个主按钮

### 3.1 给用户看的“主状态”

五组状态只在后台用。给用户看的只有一个主状态，加一句说明，加一个主按钮。按下面的顺序取第一个命中的：

| 顺序 | 条件 | 主状态 | 一句话说明 | 主按钮 |
|---|---|---|---|---|
| 1 | 售后不是 无 / 已关闭 | 售后处理中 / 售后已完成 / 售后未通过 | 按售后状态写，例如“已收到你的申请，1 个工作日内回复” | 查看售后 |
| 2 | 订单已取消或已关闭 | 已取消 | “这笔订单已取消，没有扣款” | 按这款再买 |
| 3 | 支付是 退款处理中 / 已退款 / 退款失败 | 退款中 / 已退款 / 退款遇到问题 | 写明金额：“¥128.00 原路退回，一般 1–3 个工作日到账” | 联系客服（退款失败时） |
| 4 | 订单已完成 | 已完成 | “戴得开心” | 按这款再买 |
| 5 | 物流 已签收 | 已签收 | “快递显示已签收，确认没问题就点确认收货” | 确认收货 |
| 6 | 物流 运输中 / 已发货 | 运输中 | 最新一条物流轨迹，没有轨迹就写“已交给 顺丰，单号 SF…” | 查看物流 |
| 7 | 物流异常 / 已退回 | 物流有点问题 | “快递遇到问题，我们在处理，有进展会通知你” | 联系客服 |
| 8 | 履约 制作中 / 待发货 | 制作中 / 待发货 | “师傅正在串你的手串，预计 2 天内发出” | 无 |
| 9 | 支付 未支付 | 待支付 | “在线支付还没开通，订单已为你保留。开通后会第一时间通知你” | 取消订单（次按钮） |
| 10 | 其他 | 处理中 | “订单正在处理” | 无 |

规则：
- 主状态只用文字颜色区分：普通用主字色，需要用户处理的（已签收待确认、待支付）用强调色，异常和退款失败用警示红。不用彩色胶囊。
- 每屏最多一个主按钮；其他动作放在页面底部的“更多”里（取消订单、联系客服、复制订单号）。
- 预计时间、退款到账时长这些数字，后端没给就不写，不要编。

### 3.2 订单进度条

详情页顶部，主状态下面放一条四步进度：**下单 → 制作 → 运输 → 签收**。当前步骤高亮，已完成的步骤下面写时间。

- 取消、退款、售后时不显示进度条，只显示主状态和说明。
- 时间来自后端给用户的进度记录（见 3.6），没有就不写。

### 3.3 物流

- 发货后物流卡片**常驻**在订单详情里，不再需要点“查看物流”展开。
- 一行承运方和单号，单号旁边放“复制”按钮（`wx.setClipboardData`）。
- 下面按时间倒序列出轨迹，最新一条加粗，默认显示 3 条，“查看全部”展开。
- 后端暂时没有轨迹时，只显示单号和“复制单号后可在快递官网查询”。接入快递轨迹查询是**需后端**的单独任务。

### 3.4 售后（需后端）

- 入口：订单 已签收 或 已完成 后 7 天内，详情页“更多”里出现“申请售后”。
- 申请页：选原因（收到有破损 / 珠子和图不一样 / 尺寸不合适 / 其他），选填说明，最多 3 张照片，提交。
- 提交后订单主状态变成“售后处理中”，详情页显示售后进度：已提交 → 审核中 → 处理中（退回 / 补寄 / 退款）→ 已完成。
- 需要后端新增：用户提交售后的接口、`allowedActions` 增加 `request_after_sale`、给用户看的售后进度字段。

### 3.5 订单列表

- 从“我的”页拆成独立的“我的订单”页（分包），“我的”页只放最近一单的入口和“全部订单 ›”。
- 顶部 5 个分类：全部、待支付、制作中、待收货、售后。归类按 3.1 的主状态：待收货 = 运输中 + 已签收。
- 每一行：手串缩略图、名字、主状态（文字颜色）、金额；需要用户处理的单（已签收待确认）在行尾直接放主按钮。
- 空状态：“还没有订单”，下面一个次按钮“去串一条”。

## 4. 需要负责人拍板

1. 待支付订单：一直保留，还是 N 天后自动关闭？
2. 售后申请期限：签收后 7 天，还是别的？
3. 客服：用微信客服（需要在公众平台开通），还是先留一个微信号？
4. 制作周期和发货时间：能不能给一个固定承诺（例如“2 天内发出”）。不能就不写。
