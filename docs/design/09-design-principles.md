# 09 设计经验：原则与检查清单

> 这份文件把 2026-11-11 到 11-12 负责人几轮意见背后的道理提炼出来，用来指导以后所有页面的设计、审查和开发验收。每条原则都写了：**是什么、为什么、怎么检查**，并附上我们自己踩过的坑。
> 负责人举的每个例子都是一类问题的样本，不是只改那一处。拿到一条意见，先问“它背后的原则是什么、全站还有哪些地方犯了同样的错”，再动手。

## 一、方向：先想清楚为谁做

### 1. 先定人群和场景，再定风格
- **是什么**：风格从目标用户的审美和使用场景推出来，不从“我觉得高级”推出来。
- **为什么**：同样是“东方感”，对文玩用户是加分，对买水晶的年轻女性是老气。
- **怎么检查**：能说出主要用户是谁、她在什么场景下用、她平时看什么（小红书高赞笔记、她喜欢的品牌），并有数据或参考支撑。
- **踩过的坑**：“素纸朱砂”中式方向，指向文玩和礼品店，被负责人一眼看出老套。

### 2. 参考同类，但学原则不抄样子
- **是什么**：看国际品牌、设计师品牌、独立站、竞品，提炼共同规律，再结合自己的条件落地。
- **为什么**：大牌好看靠的是顶级摄影，我们没有；照抄样子只会更难看。
- **怎么检查**：每条借鉴都能说清“学的是哪条原则、我们的条件下怎么做”。
- **踩过的坑**：没有实拍图，用程序画的假珠子做方向稿，怎么调颜色都难看。

## 二、视觉：克制和一致

### 3. 颜色、字号、样式有预算
- **是什么**：全站颜色、字号、圆角、按钮种类都有上限，超出要说明理由。
- **为什么**：106 种颜色、20 种字号的页面像逛超市，每块都在喊，就没有重点。
- **怎么检查**：随便截一屏，除了商品图，颜色不超过 4 种，按钮不超过 2 种。

### 4. 颜色不表达轻重，文字和按钮表达
- **是什么**：状态、提醒的轻重用文字说清楚，需要用户动手的用主按钮提示；红色只留给安全和错误。
- **为什么**：用颜色区分轻重，每加一种状态就要多一种颜色，用户也记不住哪个颜色代表什么。
- **踩过的坑**：订单状态有的灰蓝、有的黑，进度条也有彩色的一格，说不清为什么。

### 5. 能点的是圆的，只用来看的是方的
- **是什么**：按钮、输入框、标签用胶囊或圆形；照片、列表、版面用直角。
- **为什么**：手指要点的东西做成直角显得生硬、像网页；方框里放圆形按钮会打架。
- **踩过的坑**：“白盒”被理解成处处直角，输入框和标签都是方块。

## 三、页面：每页一个重点

### 6. 每页先回答三个问题
- 用户为什么来？我们希望他第一眼看到什么？他下一步做什么？
- 焦点只能有一个，主动作只能有一个。写不出来，这页就不该存在或该合并。
- **踩过的坑**：“自己串”中间页什么都没做；订单详情看不出重点；AI 配大标题加大片空白。

### 7. 屏幕面积按任务的重要程度分配
- **是什么**：用户在这页最常做的事，占最大的面积、最顺手的位置。
- **为什么**：面积就是优先级的宣言。
- **踩过的坑**：工作台的核心是挑珠子，却让手串占了大半屏，选珠区被挤成一排。

### 8. 信息分四层，各有固定位置
| 层 | 放哪 |
|---|---|
| 焦点 | 第一屏最大的位置 |
| 决策信息（做下一步前必须知道的） | 紧挨着主动作 |
| 安心信息（降低疑虑的说明） | 放在疑虑产生的地方，小字，只说一次 |
| 规则信息（很少看但必须有） | 页面底部或折叠 |
- **硬规则**：底部操作栏只放价格和一个主按钮；提醒放在用户做决定的那一刻；同一个信息只说一次。
- **踩过的坑**：“估算，以托盘为准”塞在底部栏里折行；材料安全提示一大块红色压在订单页中间，勾选框离提交按钮很远。

### 9. 用户自己的作品要被郑重地展示
- **是什么**：用户设计的手串，在详情、订单、分享里都用大图。
- **为什么**：这是产品的情感价值，比订单号更让人安心。
- **踩过的坑**：订单详情里手串缩成一行小图。

## 四、交互：省力、可见、有反馈

### 10. 让用户随时知道“现在是什么状态”
- **是什么**：选了什么、选了几个、到了哪一步、还差什么，都直接显示在界面上，不让用户去数、去猜。
- **踩过的坑**：工作台没有“已选”，用户不知道自己选了哪些、各几颗。

### 11. 每一步操作都有反馈，正面的和负面的都要
- **是什么**：同一瞬间告诉用户“发生了什么”和“现在怎么样”。成功给一点愉悦（动画、轻震动、声音）；出问题说清**原因和出路**，最好给一个一点就能解决的按钮。
- **为什么**：没有反馈，用户会重复点、会怀疑、会放弃。
- **怎么检查**：列出这页所有操作，每一项都能说出它的视觉、触感、文字反馈；所有“禁用”按钮旁边都写着为什么禁用，或者点了会解释。
- **踩过的坑**：加珠子没有提示；少于 6 颗时“串好了”直接变灰，不说原因。

### 12. 减少用户的费力
- 维度：步数、跳转次数、手指移动距离、需要记住的东西、需要输入的字、需要做的决定。
- 做法：默认值（手围先按 15cm 并明说）、记住上次的选择（地址、手围）、能撤销就不弹确认、一次确认不要两次、不让用户重复操作（登录后自动继续提交）。
- **踩过的坑**：登录页只有一个按钮，登录完还要回去再点一次提交；勾选了安全提示，提交时又弹一次确认。

### 13. 沿用用户已经熟悉的习惯
- 微信聊天的输入条和“按住说话”、电商“同意协议”勾选放在提交按钮上方、订单的“确认收货”、物流单号的“复制”。
- **为什么**：熟悉的东西不用学。自创交互要有足够大的好处才值得。

### 14. 给用户多种表达方式
- **是什么**：打字、语音、拍照，用户用哪种方便就用哪种。
- **为什么**：很多人说不清自己想要什么，但能拍一张喜欢的图。

## 五、内容：完整、准确、有依据

### 15. 内容要完整、准确，不为了放而放
- **是什么**：每一块内容都要能回答“用户为什么需要它”和“它的依据是什么”。推荐要讲清理由；没有依据的不写；满足不了用户的条件要直说。
- **踩过的坑**：AI 推荐只有图和名字，理由单薄。

### 16. 数字由规则计算，并且要验算
- **是什么**：价格、长度、颗数按项目规则算，不手写、不让模型编。设计稿里的示例数字也要按规则验算。
- **踩过的坑**：所有稿子都写着“18 颗 · 152mm · 合适”，按尺寸规则其实偏短 21mm，一直没人发现。

### 17. 讲寓意不讲功效，内容来自知识库
- 寓意、注意事项、安全提示都取自 `kb/`，过 banned 词表。

## 六、产品：完整和可传播

### 18. 按完整的生命周期检查功能
- 发现 → 定制 → 交易 → 履约 → 售后 → 评价 → 传播 → 账户 → 规则。每个环节都问：用户在这里会遇到什么情况、要做什么、我们有没有对应的页面和流程。
- 异常路径和正常路径一样重要：退款、改地址、缺货、超时、没权限、网络断了。
- **踩过的坑**：售后只有一个“申请售后”页，没有类型选择、进度、寄回、撤销；也没有地址管理、送礼、物流详情、晒单。

### 19. 每个能被截图和分享的画面都带品牌
- 工作台、分享海报、试戴照、晒单，都带品牌标识；大块空白可以用来放品牌。
- **为什么**：用户的每一次分享都是免费的内容传播。

## 七、工作方法

### 20. 举一反三
- 收到一条意见，先找背后的原则，再全站排查同类问题，最后把原则写进本文件。
### 21. 交付前用本清单自查
- 每一页过一遍第 6、8、10、11、12、16 条；每次改版过一遍全部 21 条。
### 22. 没验证过的不说“已完成”
- 浏览器里看过的写“浏览器里看过”；微信开发者工具或真机上验证过的才写“已验证”。

## 检查清单（复制到每次设计审查和 D 任务验收里）

- [ ] 这页的三个问题写得出来，焦点和主动作各只有一个（6）
- [ ] 最常做的事占最大面积、最顺手的位置（7）
- [ ] 底部操作栏只有价格和一个主按钮；说明和提醒在该在的位置，只说一次（8）
- [ ] 用户能随时看到当前状态：选了什么、到了哪步、还差什么（10）
- [ ] 每个操作都有反馈；每个禁用都有原因；每个错误都有出路（11）
- [ ] 步数、跳转、输入、确认都已经最少；有默认值、能撤销（12）
- [ ] 用的是用户熟悉的做法（13）
- [ ] 每块内容都有依据；数字按规则算过并验算（15、16）
- [ ] 文字过 banned 词表（17）
- [ ] 正常、空、加载、失败、没权限、缺货等状态都有（18）
- [ ] 截一屏：颜色不超过 4 种、按钮不超过 2 种；能点的是圆的（3、5）
- [ ] 能分享的画面带品牌（19）
