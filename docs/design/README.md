## 一句话

全站白盒：纯白底、黑字、灰色辅助字；能点的是胶囊，只用来看的是直角；颜色全部交给珠子和照片。用户来串珠子，买的是寓意和心情，所以凡是展示手串的地方，最显眼的是名字和一句寓意。“自己串”直接是全屏工作台，AI 配是一段对话，订单只给用户看一个状态和一件要做的事。

## 已定事项

### 方向和视觉
1. **全站白盒**，首页也是。预算：颜色 7 个（没有强调色、没有成功色）、字号 4 档、字重 2 档、阴影 1 种、间距 3 档、按钮 2 种加文字链接。
2. **能点的是胶囊或圆形，只用来看的是直角。**
3. **不用任何警告符号**（三角、感叹号、红点）。安全类提醒是做决定那一刻出现的平静文字；红色只给“含汞、不宜长期贴身佩戴”那一句和出错的那一行。
4. **状态字一律主字色**，不用颜色分轻重；需要用户处理的，靠主按钮提示。灰蓝强调色已从 03 和 tokens.wxss 删除。
5. **品牌**：暂名“珠养养”。字标是宋体“珠养养”加一行衬线大写“ZHU YANG YANG”，做成 SVG 图片。出现在首页导航栏、工作台托盘中央、手串详情大图、分享海报、试戴照、AR 定格照、分享落地页底部。

### 内容
6. **凡是展示一条手串的地方，最显眼的是名字 + 一句寓意**；价格、颗数、尺寸是小字或收起。
7. **寓意只用知识库的说法**（`kb/data/beads/*.json` 的 `meaning`），讲寓意不讲功效，过 banned 词表。示例款名和一句寓意是占位，正式名单由运营给。
8. **数字按规则算并验算**：手围 15cm、8mm 珠子，21 颗 168mm 合适。模型不写数字；后端没给的天数不写。
9. **价格是到手价**：全站显示的价格 = 珠子 + 运费（¥8，满 ¥99 包邮）。**取消单独的手工费**，成本并进珠子单价。确认订单只把到手价拆成珠子和运费，不跳价。金额全站写到元。

### 页面和交互
10. **4 个 tab**：首页、自己串、AI 配、我的。共 28 个页面（新增 17 个）。
11. **“自己串”直接是工作台**，没有中间页；编辑器并入，`pages/editor/editor` 删除。工作台**全屏、隐藏 tabBar**，左上角返回回到上一个 tab。重点是选珠子：托盘约三分之一屏、状态行、“已选”行、四列选珠区、底部到手价 + “串好了”。每一步操作都有反馈（08 第 2 节）。
12. **AI 配**：输入区照成熟的 AI 对话应用（输入框整行在上，按钮在框内下排）；回复 = 一条先讲寓意的消息 + 推荐卡片 + 快捷回复；详情进手串详情页。
13. **手串详情**照电商商品详情结构，热门款、AI 推荐、我的作品共用；**拍照结果是核对页，分享落地页是作品页**，都不套这个结构。佩戴与保养只在签收后的订单详情里。客服前期不做（等接入 IM）。
14. **确认订单**：默认地址自动带出；安全提示和定制商品退换说明合成一个勾选，贴着提交按钮；没有第二次确认弹层；送礼（礼盒、贺卡最多 50 字、隐藏价格）和穿绳在这里选；提交后先看到“订单已提交”。
15. **订单详情**：状态 + 一句话 + 细进度线 + 手串大图；需要用户动手才有底部主按钮，其余动作是列表行。
16. **售后**：选择类型（按阶段只列能选的，含“改手围重串”）→ 填写申请 → 售后详情 → 填写寄回单号。
17. **登录（2026-11-12 负责人改）**：逛、串、AI 配、拍照、试戴不用登录；第一次提交订单或在“我的”看订单、作品时，进手机号登录页，用微信的手机号组件，登录完接着做原来的事（04 第 22.1 节，稿 75–77）。
18. **手围不拦路**：默认 15cm 并明说，只在第一次下单时确认一次。
19. **全站一个浮动提示组件**；按钮不靠禁用来拒绝，点了说原因和出路。

### 不动的规则
20. 尺寸规则、金额按分的整数、订单状态契约、下单幂等和价格复核都不动。计价规则只通过后端任务 B1 改。不接真实支付。

## 这套方案没做什么

- 没改任何小程序代码和后端代码，只有 `docs/design/` 下的文档。
- **没在微信开发者工具或真机上验证过任何东西。** mockups-final.html 在浏览器里逐屏看过，375 宽下没有横向溢出。
- 稿子里的照片是灰色块，珠子是程序画的；换成实拍图后的观感没有验证。
- 工作台的自定义导航栏、隐藏 tabBar、tab 页上的弹层、SVG 图标和字标在真机上的表现，需要真机确认。
- 稿子和 04 里的寓意、banned 词、长度、颗数、到手价用脚本查过（寓意不一致 0、banned 0、数字错误 0）；脚本只覆盖带标记的文字和固定写法，其余文字靠人读。
- 购物袋（一单多条）没有设计。
- 结论没有用户数据验证，00 第 8 节列了一两天能做的验证办法。
