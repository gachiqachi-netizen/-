# 后台前端任务卡 · 第二波及以后

> 派活批次见 [00-dispatch.md](00-dispatch.md) 第 2 节（第 5–9 批）。第一波的“共同规矩”适用（见 [admin-wave1.md](admin-wave1.md) 开头），**但第 1 条改了**（见下面第 1 条）。
> 提示词用 [01-agents.md](01-agents.md) 第 3 节的格式（省 token 的版本）。
>
> **第二波起的规矩，为的是能并行**：
> 1. **页面卡不提交打包产物** `server/static/admin/shadcn-admin.*`。本地 `npm run build` 能过就行（PR 里贴输出）。每一批合并完，由一张很小的卡 **DB 打包** 统一打一次并提交。
> 2. **每张卡只改自己的页面文件** `admin-web/src/pages/<名字>.tsx`（D2 已经为每个菜单项建好），需要新组件就放 `admin-web/src/pages/<名字>/` 子目录。公共组件 `src/ui/*` 不改；缺公共组件就停下来问。
> 3. 文字和状态只用 `contract.ts`；订单状态只用 `opsStatus`；按钮只按后端给的 `allowedTransitions` / 权限显示。
> 4. 后端接口还没合并时：页面显示“这一块等后端 B-x”，PR 里写明。

### D3d 角色勾选表接通保存（2026-11-13 补）

## D4 做单（工单列表、工单页、质检）

- **依赖**：D2、A8d（质检人自动取账号；没合并时质检人先显示输入框，PR 写明）　**稿**：A03–A05　**只能改**：`src/pages/workOrders.tsx` 和 `src/pages/workOrders/`

**容易做错的地方**
- 工单页给做单师傅用：平板横屏（1180×820）能看清，珠子 30px 以上、编号大字；**编号珠序按顺序排成网格，不画成圆环**。
- 工序是一排五段（`CONTRACT.workOrderSteps`，发给后端的就是中文词），点一段就保存。
- 领料清单的“已领”勾选只存本机（`localStorage`，键带工单号），不上传。
- 质检四项全勾才能点“通过，可以发货”；有没勾的只能“不通过，退回重做”，原因必填。
- 模拟付款的单在顶部红字“模拟付款，不要生产”（`mockPayment`）。
- “打印工单”：用浏览器打印，打印样式只留珠序和清单。

### D6c 手工费和运费设置
